# MS605 GUI 앱 계획

여러 대의 MS605 센서를 **자동 보정·현황 확인·컨트롤**까지 직관적으로 다루는 GUI 앱의
설계 결정과 실행 계획. (2026-10-01 그릴링 세션 결과)

## 1. 목표와 전제

- **목표**: 센서 N대를 한 화면에서 보고, 버튼 몇 번으로 모으고, 한 번에 보정하고, 안전하게 설정을 바꾼다.
- **사용자**: 개발자 본인과 개발자 동료. `uv run ms605 gui`로 실행하고, 패키징된 데스크톱 앱은 v1 범위 밖이다.
- **하드웨어 제약** (UX가 따라야 하는 사실):
  - MS605는 **물리 버튼을 누른 직후 짧은 시간만** 연결을 받는다. 여러 대를 다루려면 사람이 공간을 돌며 버튼을 눌러야 한다.
  - 연결은 유휴 상태면 끊긴다. 끊기지 않게 하려면 keep-alive ping이 필요하다. 끊긴 링크는 버튼을 다시 눌러야만 복구된다.
  - 자동 보정은 기기 내부에서 진행되며, 빈 공간에서 최대 약 3분이 걸린다. 진행률은 알려 주지 않고 완료(tag62)만 알려 준다. 도중에 링크가 끊기면 학습이 초기화된다.
  - 센서는 배터리 기기다. 연결을 붙들고 있는 동안 배터리를 소모한다.
  - macOS의 BLE 주소는 **호스트마다 다른** CoreBluetooth UUID다. 같은 센서라도 노트북마다 주소가 다르다.

## 2. 설계 결정

| # | 주제 | 결정 | 이유 |
|---|------|------|------|
| D1 | 앱 형태 | **로컬 웹 앱**: Python 백엔드가 BLE 허브를 맡고, UI는 브라우저로 띄운다 | 기존 드라이버를 재사용한다. 같은 LAN의 폰으로 접속해, 현장에서 버튼을 누르며 바로 확인할 수 있다 |
| D2 | 데스크톱 껍데기 | v1에서는 하지 않는다. 필요해지면 **Tauri + Python sidecar(PyInstaller)** 로 감싼다 | UI가 껍데기와 무관한 웹 앱이므로, 나중에 감싸는 일은 순수하게 패키징 문제가 된다. Electron은 크기만 크고 이득이 없다 |
| D3 | 작업 순서 | **코어 계층을 먼저 추출**한다. CLI와 GUI가 같은 코어를 쓴다 | 지금은 연결 유지·배치 보정·클론 검증이 `cli.py`에 `print`와 섞여 있다 |
| D4 | 센서 식별 | **tag30 Device ID를 영구 키**로 쓰고, 사이트 > 센서(별명·위치 메모) 레지스트리로 관리한다. 호스트별 BLE 주소는 캐시로만 둔다 | 노트북을 바꾸거나 Linux로 옮겨도 등록 정보가 유지된다 |
| D5 | 연결 운용 | **작업 세션형**: 작업할 때만 모으고, 끝나면 해제한다 | 배터리를 아끼고 OS의 동시 연결 수 한도를 피한다. 연결되지 않은 센서는 마지막으로 알려진 값(스냅샷·보정 이력·배터리)으로 표시한다 |
| D6 | 보정 흐름 | **사전점검(재실 감지 경고) → 시작(즉시 / N초 카운트다운 / 시각 예약) → 센서별 진행 → 끊긴 센서만 재시도 → 전후 임계값 비교** | 폰으로 방 밖에서 시작할 수 있다. 진행 막대는 기기가 보낸 진행률이 아니라 경과 시간 / 약 3분이다 |
| D7 | 편집 모델 | **초안 → 차이 미리보기 → 적용 → 재조회 검증**. 적용 전 스냅샷을 자동 저장해 **되돌리기**를 지원한다. 클론도 "여러 센서에 같은 초안 적용"으로 흡수한다 | 쓰기는 기기 동작을 바꾸고, 반쯤 적용된 상태가 생길 수 있다 |
| D8 | 일괄 임계값 | **상대값(현재 대비 ±n)이 기본**이다. 절대값 덮어쓰기는 명시적으로 고를 때만 하고, 이때 경고를 띄운다. 단일 센서는 실시간 막대 위의 임계선을 드래그해 절대값으로 정한다 | 존 임계값은 센서마다 다른 보정 결과이기 때문이다 |
| D9 | 스택 | FastAPI(REST + WebSocket) + **React + Vite + TS** SPA. TS 타입은 pydantic 스키마에서 생성하고, 빌드 결과물은 `ms605/gui/static/`에 넣어 패키지에 포함한다 | 드래그·실시간 막대 같은 맞춤 인터랙션을 만들 수 있다. 나중에 Tauri로 감싸기도 자연스럽다 |
| D10 | 접속 보안 | 기본은 `127.0.0.1`에만 바인딩한다. `--lan`을 주면 LAN에 열고 **실행할 때마다 새로 만드는 토큰 URL을 QR**로 보여 준다. 토큰이 없는 요청은 거부한다 | LAN의 다른 사람이 센서에 쓰거나 보정을 시작하지 못하게 한다 |
| D11 | 다중 클라이언트 | 센서 상태와 작업은 **서버가 기준**이며, WS로 모든 화면에 똑같이 보낸다. 초안은 화면별로 둔다. 보정 중인 센서는 **작업 잠금**으로 쓰기를 막는다 | 폰에서 시작한 보정이 노트북 화면에도 보여야 한다 |
| D12 | 오프라인 개발 | **프로토콜 수준 시뮬레이터** `ms605/sim.py`를 만든다. 코어 수명주기 테스트와 `ms605 gui --sim N --speed K`에 같이 쓴다 | 버튼 누르기와 3분짜리 보정 때문에 실기기 반복이 느리다. 장애 상황도 재현할 수 있어야 한다 |
| D13 | 저장소 | `platformdirs`의 사용자 데이터 디렉터리에 `registry.json`, `snapshots/`, `calibration_history.jsonl`을 둔다. 기존 `sensor_info_*.yaml`은 가져오기로 옮긴다 | 지금은 repo 루트 고정 경로라 패키지로 설치하면 깨진다 |
| D14 | 범위 | v1 = 대시보드·레지스트리·센서 모으기 + 다중 자동 보정 + 실시간 모니터 + 설정 편집·일괄 적용 + 고급 설정(서브센서·DND·시간 동기화)·이력 | — |
| D15 | 기타 | CLI는 유지하고 새 코어 위로 옮긴다(동작 동일). UI 언어는 한국어로 하고 문자열은 한곳에 모은다. 다국어 지원은 v1 범위 밖이다 | — |

## 3. 목표 구조

```
ms605/
  protocol.py, models.py      순수 프레임/모델 (기존)
  driver.py                   MS605: 단일 링크 요청/응답 (버그 수정)
  events.py                   LinkState, LiveRadar, PirChanged, CalibrationProgress,
                              CalibrationResult, FrameDropped ... (타입 있는 이벤트)
  session.py                  DeviceSession: 연결·keep-alive·끊김 감지·상태 이벤트·작업 잠금
  calibration.py              보정 상태 머신 (idle→starting→learning→done|failed|lost|cancelled)
  fleet.py                    Fleet: 연속 스캔·수집, 일괄 보정(사전점검/즉시/카운트다운/예약),
                              초안 적용(검증·스냅샷·되돌리기)
  registry.py, storage.py     Device ID 레지스트리, 호스트 주소 캐시, 스냅샷·이력
  sim.py                      SimMS605 (가짜 BleakClient + 가상 기기)
  cli/                        Fleet/DeviceSession 사용 — 출력만 담당
  gui/server.py               FastAPI: REST + /ws, 토큰 인증, 정적 파일 서빙
  gui/static/                 빌드된 SPA
web/                          Vite + React + TS 소스
```

이벤트 흐름: `driver` push → `session`이 타입 있는 이벤트로 변환 → `Fleet`의 이벤트 버스 →
(CLI 출력 | GUI WS 브로드캐스트). 핸들러 예외는 격리해서 `FrameDropped`/에러 이벤트로 보낸다.

## 4. 마일스톤

### M0 — 코어 버그 수정 + 시뮬레이터 + 수명주기 테스트
베이스 로직 리뷰 결과를 수정한다. 아래 3건은 재현 스크립트로 확인했다.
- [HIGH] `reconnect()`/`disconnect()`가 대기 중인 future를 `cancel()`한다. 그래서 호출자가 `CancelledError`를 받고 keep-alive 루프가 죽는다. → `MS605ConnectionError`로 실패 처리한다 (`driver.py:204-213`)
- [HIGH] 배치 보정에서 BLE 예외가 감싸지지 않고 `gather`가 즉시 중단된다. 그 결과 나머지 센서가 보정 도중 disconnect된다. → BLE 예외를 `MS605ConnectionError`로 감싸고, `return_exceptions`를 쓰고, 기기별로 격리한다 (`cli.py:813-835`)
- [HIGH] `apply_profile`이 검증 없이 쓰기부터 한다. 그래서 잘못된 프로파일이면 일부만 쓴 뒤 `ValueError`가 나고, `zone_enable` 길이가 틀리면 존이 조용히 꺼진다. → `ConfigProfile.validate()`로 쓰기 전에 전체를 검증한다
- [MEDIUM] status가 여러 개인 응답에서 첫 번째만 검사한다. / push 핸들러 예외가 같은 알림의 응답까지 삼킨다. / `FrameReassembler`가 tail을 확인하지 않고, 길이 상한도 없다. / 쓰기 도중 취소되면 반쪽 프레임이 남고 `_pending`이 누수된다. / `disconnected_callback`이 없고, `connect()` 실패 시 연결이 누수된다. / 보정 핸들러가 해제되지 않는다. / 센서를 모으는 동안 keep-alive가 없다. / CRC 오류 응답을 그대로 쓴다
- [LOW] 빈 값이 오면 `IndexError`가 난다. / 디스패치 도중 핸들러를 제거하면 다음 핸들러를 건너뛴다. / 보정 이력 경로. / `--collect` 중단 시 정리가 없다. / 메뉴 예외 처리. / 스캔 결과의 RSSI
- `sim.py`: 버튼 누름과 연결 창, 유휴 끊김, 보정(배속), tag55 실시간 스트림, 장애 주입(링크 끊김·status 오류·짧은 tag55)
- **완료 기준**: 위 HIGH 3건마다 시뮬레이터 기반 회귀 테스트가 있고, 전체 테스트와 ruff가 통과한다.

**M0과 병행 — 실기기 측정** (시뮬레이터 파라미터와 UX 수치의 근거):
1. 버튼을 누른 뒤 연결을 받는 시간
2. 유휴 상태에서 링크가 끊기기까지의 시간과 필요한 ping 주기
3. tag51을 쓸 때 민감도(tag61)가 CUSTOM(4)으로 바뀌는지, 그리고 일괄 적용 시 쓰기 순서
4. macOS / Linux에서 동시에 유지할 수 있는 BLE 연결 수
5. tag30 Device ID가 기기마다 고유하고 리셋 후에도 그대로인지
6. 보정 중 keep-alive가 학습에 영향을 주는지

### M1 — 코어 추출
- `events` / `session` / `calibration` / `fleet` / `registry` / `storage`를 구현하고, CLI를 새 코어 위로 옮긴다.
- **완료 기준**: 기존 CLI 명령의 동작과 출력이 같다. 시뮬레이터로 수집 → 보정 → 클론 종단 테스트가 통과한다. 코어에는 `print`와 `_ui` 의존이 없다.

### M2 — GUI 뼈대
- FastAPI(REST + `/ws`), `--lan` 토큰 + QR, React 스캐폴드, pydantic → TS 타입 생성.
- 화면: 대시보드(레지스트리 전체, 연결된 센서는 실시간·나머지는 마지막 값), 센서 모으기(버튼 누름 감지 → 새 센서 등록), yaml 가져오기.
- **완료 기준**: `ms605 gui --sim 7`로 노트북과 폰에서 동시에 접속해, 같은 상태가 보인다.

### M3 — 실시간 모니터 + 다중 자동 보정
- 센서별·존별 막대(현재 CLI 막대와 같은 의미: 막대가 tick을 넘으면 초과), PIR, 서브센서별 재실.
- 보정: 사전점검 → 즉시/카운트다운/예약 → 진행 → 끊긴 센서만 재시도 → 전후 비교 → 이력 저장.
- **완료 기준**: 시뮬레이터에서 7대 중 1대를 보정 도중 끊어도 나머지 6대가 성공한다. 폰에서 시작한 보정이 노트북 화면에도 보인다.

### M4 — 설정 편집 + 고급 설정·이력
- 초안 → 차이 → 적용 → 재조회 검증 → 되돌리기, 일괄 상대값 / 절대값, 임계선 드래그, 존 활성화.
- 서브센서 존·타이밍, DND, 시간 동기화, 이력 조회(실험적 API로 표시).
- **완료 기준**: 시뮬레이터에 status 오류를 주입해 부분 실패를 만들면 센서별로 표시되고, 되돌리기로 원래 상태가 복원된다.

### M5 — 실기기 종단 검증
- 실제 사이트(7대 규모)에서 모으기 → 보정 → 편집 → 되돌리기 전 과정을 수행한다.
- 시뮬레이터와 실기기의 차이를 기록하고 시뮬레이터에 반영한다.

## 5. 열린 질문

- 사전점검의 "재실" 판정을 무엇으로 할지: tag55 sub-sensor presence만으로 충분한가, 아니면 PIR까지 볼 것인가.
- 예약 보정 동안 노트북이 잠자기에 들어가지 않게 하는 방법 (macOS `caffeinate` 연동).
- 레지스트리를 여러 노트북이 공유할 필요가 있는가 (v1은 로컬 파일 + 내보내기·가져오기).
