# ms605-ble

[English](README.md) | **한국어**

Meross MS605 재실 감지 센서의 로컬 BLE 설정 채널을 제어하는 비공식 Python
라이브러리이자 명령줄 애플리케이션입니다. 클라우드 계정 없이 설정 읽기·복제,
구역별 임계값과 민감도/DND 조정, 실시간 레이더/PIR 모니터링, 단일·다중 센서
공간 학습을 수행할 수 있습니다.

이 저장소가 공개하는 것은 독자적으로 작성한 상호운용 명세, 구현, 연구 도구,
합성 테스트입니다. 애플리케이션 바이너리, 디컴파일된 벤더 소스, 원시 Bluetooth
캡처, 실제 기기 프로파일과 그 밖의 비공개 연구 데이터는 공개하지 않습니다.

> [!WARNING]
> 이 프로젝트는 실험적이며 제조사와 무관합니다. BLE 쓰기는 기기 동작을 바꿀 수
> 있습니다. 소유했거나 시험 권한이 있는 기기에만 사용하고, 읽기 전용 동작부터
> 시작하며, 중요한 변경은 기기에서 다시 확인하세요. 이력 API는 명시적으로
> 실험 기능입니다.

## 주요 특징

- [`bleak`](https://github.com/hbldh/bleak)을 통한 macOS, Linux, Windows의
  직접 로컬 BLE 동작.
- 대화형 앱과 스크립팅용 저수준 CLI.
- 민감도, 구역 임계값·할당, DND, 시각 동기화, 서브센서 설정, 실시간 출력의
  읽기와 쓰기.
- keep-alive를 포함한 단일·다중 센서 자동 보정.
- 선택적 백업과 복제를 위한 설정 프로파일.
- 순수 프레임/모델 모듈과 합성 fixture 및 비식별 상호운용 상수만 사용하는
  라디오 비의존 테스트 스위트.
- 스캔, GATT 열거, 알림 로깅, 통제된 쓰기, 오프라인 btsnoop 디코딩을 위한
  독립 연구 도구.
- 아래에 명세된 개인정보·지식재산 안전 역공학 절차.

## 빠른 시작

Python 3.10 이상과 [`uv`](https://docs.astral.sh/uv/)가 필요합니다.

```bash
./scripts/setup.sh
./scripts/test.sh
./scripts/run.sh
```

MS605는 보통 물리 버튼을 누른 직후 짧은 시간에만 연결을 허용합니다. 센서에
연결된 다른 앱을 닫고 버튼을 누른 다음 명령을 실행하세요.

```bash
uv run ms605                         # 대화형 UI
uv run ms605 read                    # 검색 후 설정 읽기
uv run ms605 calibrate               # 센서 한 대 또는 여러 대 선택
uv run ms605 clone --help            # 선택적 설정 복제
uv run ms605-driver scan             # 저수준 검색
uv run ms605-driver --address <ADDR> read
```

현재 버전과 정확히 일치하는 전체 명령 설명은 `uv run ms605 --help`와
`uv run ms605-driver --help`를 사용하세요.

### 라이브러리 예제

```python
import asyncio

from ms605 import MS605


async def main() -> None:
    devices = await MS605.scan(timeout=6)
    if not devices:
        raise RuntimeError("MS605를 찾지 못했습니다. 버튼을 누르고 다시 시도하세요")

    sensor = MS605(devices[0])
    await sensor.connect()
    try:
        config = await sensor.read_config()
        print(config.sensitivity, config.zone_thresholds)
    finally:
        await sensor.disconnect()


asyncio.run(main())
```

원시 관찰은 연구의 임시 입력일 뿐, 저장소 자산이나 빌드 의존성이 아닙니다.

수 있는 공개 연구 기록은 [docs/evidence/README.md](docs/evidence/README.md)에 있습니다.

## 이 프로젝트를 역공학한 방법

이 절은 비공개·독점 자료를 보관하지 않으면서도 유용한 공개 프로젝트를 만들기 위한
반복 가능한 방법과 통제 절차를 명세합니다. 접근 통제를 우회하거나 시험 권한이 없는
시스템을 조사할 권한을 부여하는 문서가 아닙니다. 적용되는 법률과 약관을 확인하세요.

### 1. 좁은 상호운용 질문에서 시작한다

독립 클라이언트에 필요한 최소 동작을 정의합니다. 이 프로젝트의 범위는 기기의 로컬
BLE 설정 채널, 즉 검색, GATT 역할, 설정 읽기·쓰기, 알림, 공간 학습이었습니다.
계정, 자격 증명, 클라우드 API, 관련 없는 커미셔닝 흐름은 전송 방식을 구분하는 데
필요하지 않은 한 제외했습니다.

페이로드를 보기 전에 서로 경쟁하며 반증 가능한 가설을 작성합니다. 초기 전송 가설은
다음과 같았습니다.

1. 구형 벤더 BLE/JSON 전송 방식;
2. 표준 커미셔닝 전송 방식;
3. 별도의 바이너리 설정 서비스.

의도한 동작마다 비공개 연구 노트에 네 가지를 기록합니다.

- 외부에서 확인할 수 있는 예상 결과;
- 변하지 않아야 할 바이트나 필드;
- 변해야 할 필드;
- 해당 가설을 반증할 관찰 결과.

하나의 가설이 여러 동작을 설명하고, 가능한 경우 양방향으로 파싱되며, 독립적으로
생성될 때에만 프로토콜 주장으로 승격합니다.

### 2. 로컬 출처 원장을 유지한다

조사 권한이 있는 앱 사본과 기기만 사용합니다. 분석 전에 다음을 로컬에 기록합니다.

| 필드 | 기록할 내용 |
| --- | --- |
| 애플리케이션 식별 | 정확한 패키지/애플리케이션 식별자 |
| 버전 | 버전 이름, 버전 코드, 플랫폼 |
| 취득 | 권한 있는 취득 경로와 날짜 |
| 무결성 | 정확한 분석 대상의 SHA-256 |
| 패키징 | 기본 패키지, 분할 패키지, 관련 바이트코드 컨테이너 |
| 환경 | OS, 런타임, 디컴파일러/디스어셈블러, 도구 버전 |
| 재배포 | 바이너리와 벤더 파생 소스는 항상 `no` |

이 원장은 분석 대상을 재배포하지 않고 결과를 재현하게 합니다. 로컬 경로,
타임스탬프, 계정 문맥, 기기 식별자가 포함되면 저장소 밖에 둡니다. 과거 분석 대상의
버전이나 해시를 추측하지 말고, 다시 취득해 분석을 반복합니다.

최초 분석 원장은 이 비식별 저장소에 공개되어 있지 않으므로 과거 정적 분석을 정확히
재현하는 것은 현재 불가능합니다. 기여자는 독립적으로 취득한 권한 있는 자료로 방법을
재현할 수 있지만, 공개된 버전과 SHA-256이 일치하지 않으면 같은 분석 대상이었다고
주장해서는 안 됩니다. 앞으로는 바이너리나 로컬 경로 없이 확인 가능한 버전·해시 등
안전한 원장 필드를 공개해야 합니다.

### 3. 정적 분석에서는 인터페이스 사실만 파생한다

정적 분석은 동작을 찾는 지도이지 이 프로젝트의 소스 재료가 아닙니다. 사용자 동작을
하나씩 다음 순서로 추적합니다.

1. 스캔 필터와 GATT 서비스/특성 선택을 찾는다.
2. UI 동작에서 데이터 모델과 BLE 호출까지 추적한다.
3. 직렬화, 무결성 검사, 청킹, 응답 라우팅을 찾는다.
4. 필드 순서·폭·바이트 순서·상태 전이 같은 인터페이스 사실만 기록한다.
5. 그 사실을 독자적인 문장으로 [`docs/SPEC.md`](docs/SPEC.md)에 다시 쓴다.

벤더 메서드 본문, 주석, 클래스 구조, 디컴파일 결과를 번역하거나 붙여넣지 않습니다.
공개 구현은 독점 소스에 접근하지 않아도 이해하고 유지보수할 수 있어야 합니다.

### 4. 동적 BLE 실험을 격리한다

소유했거나 시험 권한이 있는 하드웨어에서 통제된 세션을 사용합니다.

- 가능하면 전용 시험 휴대전화나 프로필을 사용합니다.
- 시계, 이어폰, 자동차와 그 밖의 BLE 액세서리를 끊습니다.
- 가능하면 관련 없는 앱과 백그라운드 동작을 중지합니다.
- 새 로그에서 정확히 하나의 이름 붙인 동작만 수행합니다.
- 실제 시각 대신 `T+0`, `T+5` 같은 상대 시각을 기록합니다.
- 정상 UI 범위 안에서 한 설정만 바꾸고 실험 후 복원합니다.
- 먼저 대상 GATT 서비스를 열거해 ATT 핸들의 역할을 명시합니다.
- 예상 응답이나 알림을 받은 즉시 세션을 끝냅니다.
- 원시 세션은 Git이 무시하는 임시 로컬 공간에만 둡니다.

격리는 개인정보뿐 아니라 정확성을 위한 통제입니다. 시스템 전체 Bluetooth 로그에는
관련 없는 기기 트래픽, 고정 식별자, 이름, 네트워크 정보, 위치, 시각, 앱 활동이
들어갈 수 있습니다.

### 5. 전송 계층을 아래에서 위로 재구성한다

원하는 값을 바이트 스트림에서 검색하지 말고 각 계층을 독립적으로 디코딩합니다.

```text
HCI ACL 레코드
  -> L2CAP 재조립
  -> ATT 쓰기와 알림
  -> 애플리케이션 청크 재조립
  -> 프레임 봉투
  -> TLV 속성
  -> 동작 의미
```

연결과 특성 역할을 기준으로 쓰기와 알림을 묶습니다. 재조립은 선언된 길이와 봉투
경계를 사용하며, 패킷 시각만을 구분자로 사용하지 않습니다. 동일한 동작을 반복해
메시지 카운터·검사값 같은 동적 필드와 의미 있는 페이로드 바이트를 분리합니다.

### 6. 차분 실험으로 프레이밍과 TLV 구조를 추론한다

후보 구조를 한 사례가 아니라 모든 통제 세션에 대입합니다. 유용한 순서는 다음과
같습니다.

1. 한 동작을 반복해 가변 필드를 찾는다.
2. 열거형 설정을 허용된 모든 값으로 바꾼다.
3. 나머지를 고정하고 구역 또는 서브센서 필드 하나만 바꾼다.
4. 쓰기 전후 읽기를 비교한다.
5. 단일·다중 속성 메시지를 모두 시험한다.
6. 동작별 예외가 필요한 후보는 버린다.

태그 폭, 길이 폭, 바이트 순서, 부호, 배열 stride, 패딩을 따로 결정합니다. 실험으로
의미를 구분할 때까지 알 수 없는 값은 불투명 바이트로 보존합니다.

### 7. 무결성 알고리즘을 독립적으로 식별한다

검사 알고리즘과 적용 범위를 서로 다른 가설로 취급합니다. 각 후보에 대해 다음을
확인합니다.

- 구조가 다른 여러 프레임을 시험한다.
- 제안한 적용 바이트 구간을 바꿔 본다.
- 표준 체크 벡터가 있으면 확인한다.
- 한 바이트를 뒤집어 검사가 실패하는지 확인한다.
- 독자적으로 작성한 인코더로 완전한 프레임을 생성한다.
- 생성한 프레임을 별도 코드 경로로 파싱한다.

현재 공개 명세에서 CRC-16/CCITT-FALSE는 ASCII `123456789`에 대해 `0x29B1`을
생성해야 합니다. 이 표준 벡터는 로컬 알고리즘의 대표적인 적합성을 확인하지만,
모든 입력에 대한 정확성이나 기기 호환성을 증명하지는 않습니다.

### 8. 동작 행렬로 의미를 확립한다

와이어 구조와 사람이 이해하는 의미는 서로 다른 주장입니다. 의미 변수 하나만
격리하는 행렬을 사용합니다.

| 실험 | 고정 | 변경 | 확립하는 것 |
| --- | --- | --- | --- |
| 동일 동작 반복 | 화면의 설정 | 메시지 인스턴스 | 카운터와 가변 필드 |
| 열거형 전체 순회 | 기기와 화면 | 순서가 있는 선택 하나 | 후보 열거형 인코딩 |
| 구역 하나 변경 | 다른 모든 구역 | 임계값 쌍 하나 | 배열 stride와 바이트 순서 |
| 읽기 -> 쓰기 -> 읽기 | 연결과 대상 | 속성 하나 | 읽기/쓰기 대응 |
| 장시간 동작 시작 | 초기 기기 상태 | 명령 하나 | 즉시 응답과 후속 푸시 구분 |

광범위한 퍼징과 잠재적으로 파괴적인 쓰기를 피합니다. 정상 UI 범위와 가설을 구분할
수 있는 가장 작은 실험을 우선합니다.

### 9. 분석한 프로그램이 아니라 명세에서 구현한다

구현 경계는 다음과 같습니다.

```text
관찰 노트 -> 동작 명세 -> 독자 작성 프로토콜 코드 -> 드라이버 -> CLI
```

런타임 패키지는 비공개 자료를 import하거나 벤더 바이너리를 요구해서는 안 됩니다.
[`tools/`](tools/) 아래 도구는 의도적으로 런타임 패키지를 import하지 않아, 공통
프레이밍·검사값 불변식을 두 번째 구현 경로에서 확인할 수 있습니다. 이는 구현 간
차이를 찾는 장치이지 독립 저작이나 외부 기기 근거가 아닙니다. 저수준 도구와 런타임
명령 계약의 차이는 조용히 동일시하지 말고 명시해야 합니다.

프로토콜 파싱은 순수 함수로 두고 BLE I/O와 분리합니다. 알 수 없는 TLV는 파싱된
프레임에 그대로 보존해 새 펌웨어를 추측으로 디코딩하지 않도록 합니다.

### 10. 결과를 합성 회귀 테스트로 변환한다

공개 테스트는 명세만으로 만들 수 있어야 합니다. 벡터를 커밋하기 전 다음을 수행합니다.

1. 메시지 ID와 카운터를 교체한다.
2. 모든 타임스탬프를 고정된 합성 epoch로 교체한다.
3. 이름, 주소, CoreBluetooth 식별자를 포함한 기기/세션별 UUID, 기기 ID,
   계정처럼 보이는 값을 교체하되 상호운용에 필요한 프로토콜 UUID 상수는 유지한다.
4. 센서값과 설정값을 의도적으로 고른 합성 패턴으로 교체한다.
5. 길이와 CRC를 처음부터 다시 계산한다.
6. round trip과 실패 사례를 오프라인에서 확인한다.
7. 비공개 세션에서 변하지 않은 인접 바이트가 없는지 확인한다.

실제 패킷에서 눈에 띄는 몇 필드만 마스킹하는 것으로는 부족합니다. 검사값, 패딩,
시각, 이웃한 값이 원래 세션을 식별할 수 있습니다.

공개 스위트는 표준 CRC 동작, 프레임 round trip, 잘못된 입력, 검사값 실패 보고,
청킹/재조립, 메시지 ID rollover, 광고 매칭, 합성 명령·응답·푸시 모델을 다룹니다.

### 11. 근거보다 강하게 말하지 않는 신뢰도 라벨을 사용한다

공개 저장소는 세 가지 라벨을 사용합니다.

| 라벨 | 의미 |
| --- | --- |
| **구현됨 / 저장소 검증됨** | 코드에 동작이 있고 합성 fixture 또는 비식별 프로토콜 상수로 테스트됩니다. 모든 하드웨어 호환성을 뜻하지 않습니다. |
| **실험적** | 코드가 가능한 모델을 표현하지만 공개 근거가 기기 동작, 의미, 페이지 처리, 펌웨어 범위를 확립하지 못합니다. |
| **미확인 / 범위 밖** | 근거가 없거나 충돌하며, 제외한 흐름이 필요합니다. |

비공개 근거를 삭제한 뒤에는 현재 저장소가 실제 기기의 바이트 단위 관찰을 독립적으로
증명한다고 주장해서는 안 됩니다. 유지관리자가 비공개로 동작을 재현할 수는 있지만,
공개 신뢰도 변경에는 비식별 보고와 합성 회귀가 필요합니다.

### 12. 원시 데이터를 공유하지 않고 결과를 재현한다

유용한 이슈 또는 pull request에는 다음이 포함됩니다.

- 공개해도 안전한 경우 앱 버전과 SHA-256;
- 고정 기기 식별자를 제외한 펌웨어 버전;
- 수행한 단일 동작과 예상 결과;
- 실제 시각 대신 상대 순서를 사용한 필드 단위 비식별 차이;
- 도구 버전;
- 새로 생성한 합성 테스트 벡터;
- 요청하는 신뢰도 라벨 변경.

캡처, 앱 패키지, 디컴파일 소스, 버그 리포트, sysdiagnose 아카이브, 실제 설정
프로파일을 첨부하지 마세요. 검토자가 필드 단위 설명과 합성 회귀만으로 주장을 평가할
수 없다면 해당 주장은 실험적으로 남습니다.

### 13. 파생이 끝나면 비공개 근거를 삭제한다

원시 연구 자료는 임시 자료이며 Git 브랜치에 보관하지 않습니다. 한 결과의 완료 조건은
다음과 같습니다.

1. 최소한의 파생 인터페이스 사실을 독자 문장으로 기록한다.
2. 벤더 코드를 복사하지 않고 구현한다.
3. 합성 성공 테스트와 유용한 경우 실패 테스트를 추가한다.
4. 남은 모호성과 호환성 한계를 기록한다.
5. 로컬 원시 세션과 임시 디컴파일 결과를 삭제한다.

이렇게 하면 개인정보나 독점 자료 없이도 연구의 의미, 즉 반복 가능한 방법, 계약,
구현, 반증 가능한 테스트를 보존할 수 있습니다.

## 저장소 데이터 정책

### 절대 커밋하지 않는 것

- APK, XAPK, IPA, DEX, 펌웨어 이미지, 디컴파일된 벤더 소스.
- 원시 HCI/btsnoop, PacketLogger, pcap, bugreport, sysdiagnose 파일.
- 실제 BLE/MAC 주소, CoreBluetooth 식별자, 기기 ID·이름, 계정 ID,
  SSID/BSSID, 좌표, 로컬 파일시스템 경로.
- 실제 세션 시각과 관련 없는 기기·애플리케이션 트래픽.
- 실제 설정 프로파일, 보정 이력, 센서 텔레메트리.
- 합성 등가물을 만들 수 있는데 실제 세션에서 그대로 복사한 페이로드.

### 공개 가능한 자료

- 독자적으로 작성한 프로토콜 설명과 도식.
- 상호운용에 필요한 인터페이스 상수.
- 비공개 근거에 의존하지 않는 독자 작성 소스 코드.
- 길이와 무결성 필드를 다시 생성한 합성 프레임.
- 비식별 집계 관찰과 명시적 신뢰도 라벨.
- 기여자가 권한 있는 입력을 직접 취득하도록 하는 재현 절차.

`.gitignore`는 안전장치이지 개인정보 스캐너가 아닙니다. 매 커밋 전에
`git diff --cached`를 검토하고, 새 바이너리 파일은 정체를 확인할 때까지 의심스러운
자료로 취급하세요.

### 비공개 자료가 실수로 커밋된 경우

후속 삭제 커밋으로 숨기지 마세요. Git 이력에는 객체가 남습니다. 새 push를 중단하고,
영향받은 모든 ref를 식별하고, 노출된 비밀값이 있으면 교체하고, 해당 이력을 재작성한
뒤 정확한 lease로 원격을 갱신합니다. 새 clone에서 경로, 문자열, 객체 ID에 접근할 수
없는지 확인합니다. 필요하면 호스팅 제공자에게 캐시 화면이나 pull request 보존 데이터
삭제를 요청합니다. 기여자는 오염된 이력을 다시 merge하지 말고 기존 clone과 브랜치를
폐기해야 합니다.

## 개발과 검증

```bash
uv sync --frozen
uv run pytest -q
uv run ruff check .

uv run python tools/scan.py --self-test
uv run python tools/enumerate.py --self-test
uv run python tools/notify_logger.py --self-test
uv run python tools/replay.py --self-test
uv run python tools/btsnoop_att.py --self-test
```

의존성을 사용할 수 있게 된 뒤에는 위 테스트와 도구 self-test가 네트워크와 라디오를
사용하지 않습니다. 로컬 캐시가 불완전하면 `uv sync --frozen`은 패키지 레지스트리에
접속할 수 있습니다. 하드웨어 검증은 별도의 명시적 활동이며 이 README의 격리·데이터
처리 규칙을 따라야 합니다.

프로토콜 동작을 변경할 때는 다음을 지킵니다.

1. [`docs/SPEC.md`](docs/SPEC.md)와 신뢰도 경계를 갱신한다.
2. 합성 회귀 테스트를 추가하거나 변경한다.
3. 파싱/모델 로직을 라디오 I/O와 분리한다.
4. 전체 오프라인 검증을 실행한다.
5. 스테이징된 diff에 비공개 또는 복사된 자료가 없는지 검사한다.

## 호환성과 비제휴 고지

동작은 펌웨어, 모바일 OS BLE 백엔드, 플랫폼에 따라 달라질 수 있습니다. 저장소 테스트
스위트는 공개된 소프트웨어 계약을 검증할 뿐 모든 기기/펌웨어 조합을 검증하지 않습니다.
Meross는 해당 소유자의 상표입니다. 이 프로젝트는 Meross와 제휴하거나 Meross의 보증·
지원을 받지 않습니다.
